# 진단 기록 — 찾아낸 결함, 폐기된 가설, 미해결 문제

모든 항목에 측정 근거를 붙인다. 근거 없는 추정은 그렇다고 표시한다.

## A. 고친 결함

### 1. `count_head_end` 배분이 균등보다 나빴다 ✅

로그 공간에서 **1.7~1.9배 과분산**. `exp()` 후 전체 가닥의 **94 %** 를 상위 10 % 쌍에
쏟아붓는데 그 쌍 선택이 거의 무작위 (GT 배분과 상관 **0.09**).

| 배분 | SC r |
|---|---|
| 예측 (`count_head_end`) | 0.567 |
| 균등 | 0.679 |
| **템플릿** | **0.853** |
| GT (오라클) | 0.863 |

원인: `edge_count_loss` 가 log1p MAE 라 **분산 보정 압력이 없다**. `sc_end` 는 `sc_pass`
보다 16배 희소하고 꼬리가 길어 그대로 터졌다.
→ **train 템플릿 배분으로 교체** (`template_counts`).

### 2. VAE 사전분포가 실제 다발 위치를 벗어났다 ✅

`z ~ N(mu_pair, I)` 로 뽑으면 pair 별 복셀 dice 가 **0.053** (실제 표본끼리의 천장 0.597).
→ **train latent bank KDE 샘플링으로 교체** (dice 0.090, SC r +0.057).

### 3. WM 분할 마스크의 뇌실 구멍 ✅

템플릿 뇌 마스크가 뇌실을 구멍으로 남기는데(10,714 복셀), 정육면체 구조요소로 침식하면
구멍이 **66,329 복셀**로 부풀어 뇌실 주변 백질이 통째로 잘리고 상자 모양 인공물이 생겼다.
→ **구멍을 먼저 메우고 구형 구조요소로 침식**. assert 로 내부 구멍 없음을 검사.

### 4. route loss 가 길이를 폭주시켰다 ✅

route loss(pos_weight=5)는 "많은 ROI 를 지나라"고 요구하는데 길이 제약이 없으면
**길게 헤매는 쪽이 싼 해법**이 된다. 실측: 생성 길이 111 mm → **323 mm** (GT 103 mm),
val pair 정확도 0.333 → 0.293, SC r 0.813 → 0.730.
→ `gen_length` 손실 추가 + `route_pos_weight` 5 → 2.

### 5. 절대 스케일이 48배 작았다 ✅

`sc_magnitude_loss` 가 총합을 정규화한 뒤 비교해 절대 스케일 정보가 손실에서 사라졌다
(패턴 r=0.81, CCC=0.02). 전역 배율 하나로 CCC 0.024 → **0.817**.
→ `count_head`, `scale`, `rmse` 손실 추가.

### 6. intensity 정규화가 [0,1] 을 벗어났다 ✅

99.5 백분위를 0.6 에 맞추는 방식이라 상위 0.5 % 가 1 을 넘었다 (최대 1.208, 1.237).
→ `unit=True` 모드 추가 (백분위를 1.0 에 맞추고 clip). **재학습 필요.**

## B. 아직 안 고친 결함

### 1. weight head 미학습 ❌

`weight_mode='count'` 로 바꾸면서 자유 `weight_head` 가 gradient 를 받지 못해 초기값
~1.0 에 머문다. **그런데 검증/추론의 `tractogram_sc` 는 그 head 를 쓴다.**

| | 값 |
|---|---|
| 학습 시점 총합비 | 0.94 ~ 0.99 |
| 검증 총합비 | **0.002** |
| 검증 CCC | **0.002** |

학습과 평가가 서로 다른 것을 재고 있다. 현재는 개수 기반 생성(`generate_by_count`)으로
우회했지만 근본 원인은 그대로다.

**2026-09-05 재학습 체크포인트에서 재확인 — 그대로다.** `weight_head.net[-1].weight` 의 rms 가
**정확히 0** (0-초기화 이후 gradient 를 한 번도 못 받았다), bias 0.541 → 출력이 모든 입력에서
상수 **1.0** (std 0). 평가의 `sc["pass"]["sc_w"]` 는 이 head 를 쓰므로 보고된 SC 는 사실상
가중치 없는 통과 개수다. 총합비 0.027 은 생성 가닥 수(29k vs GT 1M)로 전부 설명된다.

### 2. anatomy feature 가 사실상 무시된다 ❌

T1 을 바꿔치기해도 결과가 거의 같다:

| count head 에 넣은 T1 | SC 상관 |
|---|---|
| 자기 T1 | 0.8108 |
| **남의 T1** | 0.8101 |
| **T1 = 0** | 0.8067 |

자기 예측 vs 남의 예측 상관 **0.9908**. 예측 평균 vs 그룹 템플릿 상관 0.856.
즉 `count_head` 는 **"(i,j) → 학습셋 평균" 조회표**다.

원인 두 층:

| 층 | 측정 |
|---|---|
| **크기** | anatomy L2 0.069 vs pair_vec 1.521 (22배). 1층 기여 변동 0.0069 vs 0.144 (21배) |
| **구조** | anatomy 가 3,321 쌍 전부에 **같은 상수**로 들어가 패턴을 못 바꾼다 |

가중치 자체는 죽지 않았다 (rms 0.065 vs 0.066). **입력이 22배 작다.**

### 3. 출력 다양성이 193배 부족하다 ❌

| 무엇끼리 | 평균 r |
|---|---|
| 원본 GT 끼리 | 0.897 |
| 생성 끼리 | **0.9995** |

개인차의 여지가 GT 0.1033 vs 생성 0.0005. 모델이 사실상 한 장의 행렬만 찍어낸다.

### 4. edge head 가 개인 연결 정보를 놓친다 ❌ (미탐색)

GT pair 목록을 쓰면 잔차가 0.026 → **0.129** 로 오른다. "어느 연결이 존재하는가"에만
0.10 어치의 개인 정보가 있는데 edge head 가 이를 못 잡는다. **아직 손대지 않은 통로다.**

### 5. 디코더 정확도가 기하의 병목 ❌

복원 오차 **3.55 mm**, 아틀라스 복셀 **2 mm** → 1.8칸 어긋남.

| latent | pair 별 dice | 천장 대비 |
|---|---|---|
| prior | 0.053 | 9 % |
| bank | 0.137 | 23 % |
| **오라클 posterior** | **0.167** | **28 %** |
| 실제 표본끼리 (천장) | 0.597 | 100 % |

**정확한 latent 를 줘도 천장의 28 % 다.** 사전분포가 아니라 디코더 자체가 병목이다.
복원 오차는 학습 내내 개선되지 않았다 (s1 3.72 → s5 3.55).

### 6. **개인차가 사라지는 지점 = 전뇌 global average pooling** ❌ (2026-09-05 확정)

재학습 체크포인트(`retrain/p4_joint/p4_joint_step3000.pt`, rigid+WM 2채널)에서 test 예측 SC 의
subject 간 상관이 **0.99997** (GT 는 0.882). 조건화 경로를 단계별로 잘라 재보았다
(`scripts/39_diag_conditioning.py`, test 6~12명).

| 단계 | subject 간 상관 | rel_spread |
|---|---|---|
| UNet stage3 공간맵 `[256,49,58,49]` | **0.575** | 0.729 |
| conv4 + `global_avg_pool` → `[512]` | **0.9996** | 0.093 |
| fc → anatomy `a` | 0.9996 | 0.092 |
| count head 최종 예측 | 0.99997 | — |

`rel_spread` = 그룹 평균을 뺀 노름 / 그룹 평균 노름.
pooling 이 **버리는** 공간 편차 성분 rel_spread **0.83**, **남기는** 채널 평균 성분 **0.13**.

즉 T1 에는 개인 정보가 남아 있는데(stage3 0.575) `AtmAdapter.encode_anatomy` 의
`global_avg_pool` 이 49×58×49 공간을 통째로 평균 내면서 지운다. rigid MNI 정합 후에는
채널 평균이 subject 간에 거의 같기 때문이다.

두 번째 층: 그렇게 나온 512-d 가 **3,321 쌍 전부에 같은 상수**로 들어간다. 남은 미세한 차이는
전역 배율만 바꾸는데 **상관은 배율 불변**이라 r 기여가 구조적으로 0 이다.

| count head 편차항 `f = log_count − log_template` | 값 |
|---|---|
| pair 간 std (subject 평균) | 0.824 |
| 같은 pair 에서 subject 간 std | **0.0277** |
| 전체 변동 중 subject 성분 | **0.96 %** |
| `f` 의 subject 간 상관 | 0.99998 |

**크기 문제(§B-2)는 재학습으로 해결됐다**: ‖a‖ 0.086 → 0.785, 1층 기여비
‖W_a·a‖/‖W_e·e‖ 1/22 → **0.57**. 그런데 개인차는 그대로다 — 커진 것은 평균이지 분산이 아니다
(‖W_a(a_i − ā)‖ = 0.097 vs ‖W_e·e‖ = 2.25, 여전히 23배 차이).

→ 남은 유일한 통로는 §F-5 / `PIPELINE_08_RETRAIN_DESIGN.md` §2⑥ **ROI 별 국소 풀링**
(stage3 출력을 아틀라스 82 ROI 로 풀링해 pair (i,j) 마다 다른 조건을 만든다).
이걸 고치기 전의 SC 지표는 "그룹 템플릿 한 장을 얼마나 잘 그리는가" 를 재고 있을 뿐이다.

## E. 개인차 문제 — 정량적 정리

### 필요한 값

그룹 템플릿이 0.944 라는 건 개인차가 전체 분산의 **10.6 %** 라는 뜻이다.
잔차를 상관 ρ 로 예측하면 ρ² 만 회수한다:

| 잔차 r | 회수 분산 | 최종 상관 | 템플릿 대비 |
|---|---|---|---|
| **0.026** (현재) | 0.07 % | 0.9445 | −0.001 |
| 0.203 (T1 측정 상한) | 4.1 % | 0.9478 | +0.003 |
| 0.30 | 9 % | 0.9502 | +0.005 |
| **0.42** | 18 % | 0.9545 | **+0.010** |
| 0.70 | 49 % | 0.9711 | +0.026 |

**템플릿을 뚜렷이 넘으려면(+0.01) 잔차 r ≈ 0.42 가 필요하다.**

### 측정된 값들

| 항목 | 값 | 판정 |
|---|---|---|
| 파이프라인 표현 용량 (오라클) | **0.866** | 충분 |
| T1 이 담은 정보 (직접 회귀 하한) | **0.203** | 부족 |
| 현재 모델이 쓰는 양 | **0.026** | 정보의 1/8 |
| 필요한 값 | 0.42 | — |

예측기를 바꿔도(ridge / RBF 커널 2종 / PCA 40·80·120 / 로그 타깃) **0.18 ~ 0.20 에서 평평**하다.
한계가 예측기가 아니라 정보라는 신호다. 다만 이건 **선형·커널 모델의 하한**이지 상한이 아니다.

### 하이브리드도 효과 없음

```
최종 = 그룹템플릿 + α × (생성 SC 의 LOO 개인편차)
```

| α | 0 | 0.5 | 1.0 | 2.0 | 3.0 |
|---|---|---|---|---|---|
| 최종 r | 0.9455 | 0.9455 | 0.9454 | 0.9448 | 0.9436 |

최적 α 에서도 **+0.0001**. 개인 신호가 0.026 뿐이라 더할 것이 없다.

### 병목의 우선순위

1. **T1 이 담은 개인 정보 자체가 약함** (0.203) — 표본 144명, T1 은 거시 구조만,
   GT SC 자체의 tractography 잡음
2. **모델이 그 0.203 중 0.026 만 사용** — 8배 격차, 학습으로 좁힐 수 있는 유일한 구간
3. 표현 용량은 충분 (0.866)

**2번을 완전히 해결해도 0.203 이 상한이라 템플릿 돌파(0.42 필요)는 어렵다.**
