# 재학습 설계안

전처리 프로토콜 전환(rigid + [0,1] + WM)으로 모델 입력이 바뀌어 기존 체크포인트는 무효다.
어차피 다시 학습해야 하므로, 지금까지 진단으로 확인된 구조 문제를 **같이** 고친다.

---

## 1. 왜 지금 구조 그대로 재학습하면 안 되는가

`PIPELINE_06_FINDINGS.md` 의 측정:

| 항목 | 값 |
|---|---|
| anatomy 입력 크기 / pair 임베딩 | **1 / 22** |
| anatomy 가 모든 ROI 쌍에 들어가는 방식 | **같은 상수** (패턴을 못 바꿈) |
| T1 을 0 으로 바꿔도 SC 상관 | 0.8108 → **0.8067** |
| 생성 SC 끼리의 상관 | **0.9995** (GT 끼리는 0.897) |
| 모델이 쓰는 개인 정보 / T1 이 담은 양 | 0.026 / 0.203 |

**WM 채널을 추가해도 같은 22배 눌린 경로로 들어간다.** 입력 정보를 늘리는 것만으로는
anatomy 가 다시 무시된다. 구조를 같이 고쳐야 한다.

## 2. 바꾸는 것 5가지

### ① 입력 2채널

```
[1, 1, 193,229,193]  →  [1, 2, 193,229,193]
                          ch0 = rigid T1, [0,1] 정규화
                          ch1 = WM 확률, 0~1
```

UNet 첫 conv 를 `in_channels=1 → 2` 로 확장하고 **새 채널 가중치를 0 으로 초기화**한다.
ATM 사전학습 가중치를 보존한 채 WM 경로만 새로 학습된다 (시작 시점 출력은 기존과 동일).

주의: WM 은 T1 의 결정론적 함수라 **정보가 새로 생기지 않는다.** 학습을 쉽게 만드는
유도 편향으로서의 가치다. ②③ 없이 이것만 하면 효과가 거의 없다.

### ② anatomy 스케일 정규화

```python
# 현재
cond = anatomy_gain * a + Proj(pair_vec) + mode_emb

# 변경
cond = Proj_a(LayerNorm(a)) + Proj_p(pair_vec) + mode_emb
```

LayerNorm 으로 두 항의 크기를 대등하게 만든다 (현재 0.069 vs 1.521).
`Proj_a` 는 항등에 가깝게 초기화한다.

**주의**: 사전학습 ConvVAE 디코더가 보던 조건 분포가 바뀐다. P0 예열 단계가 이를 흡수한다.
(이미 whole-brain 좌표 박스로 한 번 바꾼 전례가 있다 — `PIPELINE_02_MODEL.md` §3.)

### ③ 템플릿 인수분해 — **가장 효과가 클 것으로 보는 변경**

지금은 head 용량 대부분이 **그룹 평균을 외우는 데** 쓰인다. 개인차는 log MAE 에 거의
기여하지 못하는 20 % 섭동이라 무시된다.

```python
# count head (pass / end 둘 다)
log ŜC(i,j) = log1p(template(i,j)) + f(a, i, j)
#              └ 고정 buffer (train 144명 평균)   └ f 의 마지막 층 0-초기화

# edge head
logit(i,j) = logit(template_prob(i,j)) + g(a, i, j)
```

- 시작 시점에 **정확히 그룹 템플릿** (SC r 0.944) 에서 출발한다
- 남은 일이 개인차뿐이므로 **모든 기울기가 거기로 간다**
- 템플릿은 train 으로만 만들고 `register_buffer` 로 고정 (학습하지 않는다)

측정 근거: 추론에서 템플릿 배분이 학습된 `count_head_end`(0.567) 를 크게 이겼다(0.853).
모델이 힘들게 배우려는 것을 그냥 주는 편이 낫다.

### ④ weight head 학습/평가 일치

`weight_mode='count'` 로 바꾸면서 `weight_head` 가 기울기를 못 받는데 검증·추론은 그것을
쓴다 (학습 총합비 0.99 vs 검증 0.002).

**해결**: 검증도 학습과 같은 경로(개수 기반 `generate_by_count`)를 쓴다. `weight_head` 는
추론 경로에서 제거한다 — 쓰지 않는 head 를 남겨 두면 같은 함정을 반복한다.

### ⑤ 학습 중 개인차 지표 추가

지금은 개인차를 **마지막에만** 잰다. 학습 중에 보이지 않으면 무엇이 효과였는지 알 수 없다.

검증(val 31명)에 추가:

| 지표 | 정의 |
|---|---|
| `resid_r` | LOO 중심화 잔차 상관 (`PIPELINE_05_EVALUATION.md` §6) |
| `inter_subj_r` | 예측끼리의 subject 간 평균 상관 (GT 는 0.897) |
| `template_gap` | 모델 SC r − 템플릿 SC r |

`resid_r` 이 이번 재학습의 **주 목표 지표**다.

### ⑥ (조건부) 쌍별 국소 anatomy — P2 판정 후 결정

②③ 로도 `resid_r` 이 0.10 을 못 넘으면, 상수 조건화의 구조적 한계로 본다.

```python
# UNet stage3 출력 [1,256,49,58,49] 에서 ROI 별 평균 풀링 → f[82,256]
local_ij = MLP( concat(f_i + f_j, f_i * f_j) )        # 순서 불변
cond = Proj_a(LN(a)) + Proj_l(LN(local_ij)) + Proj_p(pair_vec) + mode_emb
```

**알려진 한계**: rigid 정합이라 아틀라스 ROI 위치가 그 사람 해부와 복셀 단위로 맞지 않는다
(피질에서 대략 5~15 mm). ROI 가 크므로 대부분 맞는 조직을 담지만 잡음이 섞인다.
비용이 크므로 P2 판정 뒤에 결정한다.

## 3. Phase 계획

| # | 이름 | steps | 켜는 손실 | 목적 |
|---|---|---|---|---|
| **P0** | `warmup` | 2,000 | recon, kl, geom | 2채널 rigid 입력 + 새 조건화에 적응 |
| **P1** | `route` | 3,000 | + endpoint, route, route_gen, gen_length, edge | 경로/끝점 회복 |
| **P2** | `count` | 3,000 | + count (**템플릿 인수분해**), seg_* | **판정 지점** |
| **P3** | `magnitude` | 3,000 | + corr, mag(none), scale, rmse, presence | 절대 스케일 |
| **P4** | `joint` | 3,000 | 전체, LR 1/3, + length | 마무리 |

총 14,000 step. 이전 12,000 step 이 약 8~9 시간이었으므로 **약 10 시간** 예상.

**드라이버는 phase 경계에서 반드시 재시작한다** (코드 변경 시 옛 config 로 죽는다,
`PIPELINE_03_TRAINING.md` §3).

## 4. 판정 기준 — 미리 정해 둔다

각 phase 끝에서 확인하고, 기준 미달이면 다음으로 넘어가지 않는다.

| 지점 | 지표 | 통과 | 미달 시 |
|---|---|---|---|
| **P0 끝** | recon RMSE | ≤ 4.5 mm | 입력/정규화 문제. 진단 후 재시작 |
| **P1 끝** | route_f1 (검증) | ≥ 0.50 | route 가중치 재조정 |
| | 생성 길이 | 80~140 mm | `gen_length` 가중치 상향 |
| **P2 끝** | **`resid_r`** | **≥ 0.10** | 아래 분기 |
| **P4 끝** | SC r | ≥ 0.88 | 재현 품질 회귀 |
| | **`resid_r`** | **≥ 0.20** | 목표 미달 |

> **관문 정정 (실행 중 발견)**: P1 관문을 처음에 0.75 로 잡았는데, 이는 **학습 로그**의
> `route_f1`(복원 경로 — encoder 가 정답 latent 를 준다) 값 0.832 를 **검증** 관문으로 잘못
> 쓴 것이다. 검증의 route F1 은 **생성 경로**를 재고 이전 학습의 검증값은 0.516~0.521 이었다.
> 0.50 이 맞는 기준이다. 같은 이름의 지표라도 어느 경로에서 쟀는지 확인해야 한다.

### P2 판정 분기

| `resid_r` | 판단 | 다음 |
|---|---|---|
| **≥ 0.10** | 템플릿 인수분해가 통했다 | P3 로 진행 |
| 0.05 ~ 0.10 | 신호는 있으나 약하다 | **⑥ 쌍별 국소 anatomy 추가** 후 P2 재실행 |
| **< 0.05** | 구조가 아니라 정보가 없다 | **중단.** 재현 파이프라인(0.88)을 완성하고 "T1 단독 개인 예측의 한계"를 결과로 보고 |

**중단 기준을 미리 못 박는 이유**: 지금까지 다섯 개의 가설이 측정으로 기각됐다
(`PIPELINE_06_FINDINGS.md` §C). 기준 없이 계속하면 효과 없는 변경을 반복하게 된다.

## 5. 기대치 — 정직하게

`resid_r` 이 최종 SC 상관에 미치는 영향 (그룹 템플릿 0.944 기준, 개인차는 전체 분산의 10.6 %):

| `resid_r` | 하이브리드 최종 r | 템플릿 대비 |
|---|---|---|
| 0.026 (현재) | 0.9445 | −0.001 |
| 0.10 | 0.9450 | +0.000 |
| **0.20** (이번 목표) | 0.9466 | +0.002 |
| 0.42 (템플릿 돌파) | 0.9545 | +0.010 |

**목표를 달성해도 그룹 템플릿을 뚜렷이 넘지는 못한다.** T1 이 담은 정보의 측정 하한이
0.203 이기 때문이다.

그래도 할 가치가 있는 이유:

1. **"모델이 개인차를 읽는다"가 성립한다** — 지금은 0.026 으로 사실상 0
2. 재현 품질(SC r 0.88, 길이 r 0.74)은 유지하면서 얻는다
3. `resid_r` 이 0.05 미만이면 **"T1 단독으로는 안 된다"를 숫자로 보인 결과**가 된다 —
   이것도 보고 가치가 있다

| 위험 | 대응 |

| ③ 템플릿에 기대어 anatomy 를 여전히 무시 | `resid_r` 을 매 검증마다 본다. 0 에 머물면 P2 에서 잡힌다 |

| 개인차 지표가 또 오염됨 | LOO 중심화 고정, 대조군(실제 streamline) 함께 기록 |

## 7. 구현 순서

```
1. WM 맵 206명 완료 확인                          (진행 중)
2. UNet 첫 conv 2채널 확장 + 입력 파이프라인       (모델)
3. LayerNorm 조건화                                (roi_pair_embedding.py)
4. 템플릿 buffer + 인수분해                        (edge_count_head.py, edge_head.py)
5. 검증에 resid_r / inter_subj_r 추가              (training/run.py)
6. weight head 를 추론 경로에서 제거               (inference/generate_sc.py)
7. 스모크 테스트 (2 subject × 20 step)             — 형상/NaN/assert 확인
8. P0 ~ P4 실행, 각 관문에서 확인
```

2~6 은 반나절, 7 은 30분, 8 은 약 10시간.

## 8. 실행 기록

### 전처리 (완료)

| 항목 | 결과 |
|---|---|
| rigid T1 | 206/206 (52초/명, 6병렬) |
| WM 확률맵 | 206/206 (36초/명). 비율 평균 0.373 ± 0.048 |
| intensity [0,1] | 최대 1.208·1.237 → 1.000 |

WM 분할에서 결함 두 개를 잡았다: ① 템플릿 마스크의 뇌실 구멍이 침식으로 66,329 복셀까지
부풀어 뇌실 주변 백질이 잘림 → 구멍을 먼저 메우고 구형 구조요소로 침식. ② 원 강도 k-means 가
밝은 이상치를 별도 클래스로 분리해 "가장 밝은 클래스"가 3~5 % 짜리 잔여물이 됨(206명 중 5명)
→ [0,1] 정규화 후 분할 + 크기 하한 0.15. 품질 관문 `assert 0.20 < WM비율 < 0.70` 이 없었으면
전부 조용히 통과했을 문제다.

### 발견한 코드 결함

| 결함 | 증상 | 수정 |
